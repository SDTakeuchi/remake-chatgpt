# Server-Sent Events（SSE）の簡単な説明

## SSEとは

**Server-Sent Events（SSE）** は、サーバーからクライアント（ブラウザ）へ**一方向**にデータをプッシュするための Web 標準の仕組みです。

- サーバー → クライアント：**ストリーミング**でテキストを送れる
- クライアント → サーバー：通常の HTTP リクエスト（POST など）で送る
- リアルタイム通知・チャットの「受信」部分・ログストリームなどに使われる

---

## フォーマット

1. HTTP レスポンスの **Content-Type** は `text/event-stream`
2. 本文は**テキスト**。1つの「イベント」は次の形で表す：

```
data: 1行目のデータ
data: 2行目も data: で始める

```

- **`data:`** の後（スペース以降）が 1 行分のデータ
- 空行 `\n\n` で 1 イベントの区切り
- 行末は `\n` または `\r\n`

### 例（このプロジェクトでの使い方）

```
data: {"content": "こんにちは"}

data: {"content": "！"}

data: [DONE]

```

- データ行：`data: ` で始まる行だけをパースして使う
- コメント行：`:` で始まる行は無視してよい（例: `: keep-alive`）
- 終了：`data: [DONE]` のように決まった文字列で「ストリーム終了」を伝える

---

## クライアント側の扱い（ブラウザ）

- **fetch** でリクエストし、`response.body` を **ReadableStream** として読む
- チャンクごとに `TextDecoder` でバイト列を文字列に変換
- バッファに貯めながら `\n` で行に分割し、`data: ` で始まる行だけを取り出してパースする

（ブラウザには `EventSource` API もあるが、GET 専用のため POST で送る本プロジェクトでは `fetch` + ストリーム読み取りを使っている。）

---

## このプロジェクトでの役割

| 役割 | 説明 |
|------|------|
| バックエンド | LLM の出力をチャンクごとに `data: {"content": "..."}` で送り、最後に `data: [DONE]` を送る |
| フロントエンド | ストリームを読んで `data: ` 行だけ処理し、受信した `content` を逐次 UI に表示する |

これにより、応答全体を待たずに「文字が打ち出されるように」表示できる。
