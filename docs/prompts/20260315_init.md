# 1. システム概要

**目的**

This project is for me to learn how I can remake the basic functionality of ChatGPT.

"The basic functionality" I mean is the chat functionality where uesrs can have a continuous conversation with the AI.


* LLMと対話するシンプルなチャットアプリを作る
* 過去セッションの保存は不要
* **1セッション内の会話履歴だけ保持**

**前提**

* ブラウザベースのWebアプリ
* LLM API（OpenAI互換など）をバックエンド経由で呼ぶ
* **Docker を用い、ローカル環境をなるべく汚さないようにする**（実行・開発環境の依存はコンテナ内に閉じる）

**技術選定方針**

* 以下の書籍・リポジトリで紹介されている技術を**優先的に使用**する。
  * 書籍: 「LangChain と LangGraph による RAG・AI エージェント［実践］入門」
  * リポジトリ: https://github.com/GenerativeAgents/agent-book
* 該当する主な技術: **LangChain**, **LangGraph**, **LCEL（LangChain Expression Language）**, **OpenAI Chat API** の扱い方、プロンプトエンジニアリング、RAG、AIエージェントの設計パターンなど。
* 実装・設計の判断に迷った場合は、上記リポジトリの各章のノートブックやサンプルを参照する。

# 2. 必須機能

## 2.1 チャット送信

ユーザーがメッセージを送信できる

### 動作

1. ユーザーがテキストを入力
2. SendボタンまたはEnterで送信
3. UIにユーザーメッセージを表示
4. バックエンドがLLM APIを呼ぶ（ストリーム有効）
5. **AIレスポンスをストリームで受け取り、受信した分から少しずつUIに表示する**（一括表示ではなく逐次表示）

---

## 2.2 会話履歴（セッション内のみ）

同じページ内では会話履歴を保持する。

### 要件

* ページロード後の会話履歴を保持
* スクロール可能
* ページリロードすると消える

---

## 2.3 スクロールチャットUI

一般的なチャットUI

要件

* メッセージは時系列
* 下に新しいメッセージ
* 自動スクロール

---

## 2.4 ローディング表示

AIの応答待ち状態を表示（ストリーム開始前、または最初のトークンが届くまで）

例

```
ChatGPT is thinking...
```

または

```
...
```

※ ストリーム開始後は、受信したテキストをそのまま逐次表示すればよい。

---

## 2.5 ストリーミング表示

* AIの返答は**ストリーム**で受け取り、チャンク（またはトークン）単位でUIに追記表示する。
* ユーザーには「文字が打ち出されるように」見えるようにする（ChatGPTのような体験）。
* ストリーム完了後に、そのメッセージを会話履歴（`messages`）に確定して保持する。

---

## 2.6 Enter送信

* Enter → 送信
* Shift + Enter → 改行

# 4. メッセージデータ構造

フロントで保持する会話履歴

```ts
type Message = {
  role: "user" | "assistant"
  content: string
}
```

配列

```
messages: Message[]
```

例

```json
[
  { "role": "user", "content": "Hello" },
  { "role": "assistant", "content": "Hi!" },
  { "role": "user", "content": "How are you?" }
]
```

# 5. API仕様

## POST /chat

LLMに問い合わせる。**レスポンスはストリーム**で返す。

### request

```json
{
  "messages": [
    { "role": "user", "content": "hello" },
    { "role": "assistant", "content": "hi" }
  ]
}
```

---

### response（ストリーミング）

* **Content-Type**: `text/event-stream`（SSE）など、ストリーム可能な形式
* チャンクごとにテキストを送信し、フロントは受信したら逐次UIに追記する
* 例（SSE）:
  * `data: {"content": "Hello"}` → `data: {"content": "!"}` → `data: {"content": " How"}` … のように `content` を送る
  * または `data: Hello` のように生テキストのみ送る形式でも可
* ストリーム終了時は終了イベントで閉じる（例: `data: [DONE]` や空イベント）

---

# 6. フロント処理フロー

### 送信時（ストリーミング対応）

```
1 ユーザー入力
2 messagesにユーザーメッセージを追加してUIに表示
3 API /chat を呼ぶ（ストリームレスポンスを期待）
4 ストリームのチャンクを逐次受信
5 受信するたびに、表示中の assistant メッセージの content に追記してUIを更新
6 ストリーム終了後、完成した assistant メッセージを messages に確定して保持
```

---

# 7. LLM呼び出し仕様（例）

バックエンド

```
POST OpenAI /v1/chat/completions
```

request

```json
{
  "model": "gpt-4o-mini",
  "messages": [...],
  "stream": true
}
```

response（ストリーミング）

```
stream: true のため、レスポンスは chunk のストリーム。
各 chunk の choices[0].delta.content を結合してフロントに転送する。
```

# 8. 非機能要件（最低限）

### レスポンス時間

* **10秒以内**：AIからの**最初のメッセージ（ファーストトークン）が表示されるまで**の時間を指す。ストリーミングでは体感の応答性はここで決まるため、全文が返却されるまでの時間は対象外とする。

### 同時送信防止

* AI応答中は入力を無効化

# 11. 環境変数・APIキーの管理（YAML）

LLMのAPIキーなどの環境変数は **YAML で管理**する。

### 方針

* 設定ファイルは `config/env.yaml`（またはプロジェクトルートの `env.yaml`）に置く
* **実際のAPIキーが書かれたファイルは Git にコミットしない**（`.gitignore` に追加）
* リポジトリには **サンプル用** の `config/env.example.yaml` のみをコミットし、キー名・構造を共有する

### 例: `config/env.example.yaml`

```yaml
# LLM API 設定（本番用の env.yaml は .gitignore に含めること）
llm:
  # OpenAI 互換 API
  api_key: ""          # 例: sk-...
  base_url: ""         # 空なら OpenAI 本家。他のプロバイダなら URL を指定
  model: "gpt-4o-mini"
```

### 例: 実際の `config/env.yaml`（ローカル用・非コミット）

```yaml
llm:
  api_key: "sk-your-actual-key"
  base_url: ""                    # OpenAI の場合は空でよい
  model: "gpt-4o-mini"
```

### 運用

* アプリ起動時に上記 YAML を読み込み、LLM クライアント（LangChain 等）に渡す
* Docker 利用時は、`env.yaml` をボリュームマウントするか、`docker-compose` の `env_file` で YAML 由来の値を渡す方法を検討する（必要に応じて YAML → `.env` 変換スクリプトを用意してもよい）
